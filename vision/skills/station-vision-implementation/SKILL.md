## 保持证据与事件含义

- 按人物和目标隔离候选。人物 ID 是当前视频中的匿名轨迹，不是自然人身份或已验证的跨镜身份。
- 二维接近、共同位移、预测框或跟踪丢失，不能单独证明拿取。区分区域候选、包裹候选、算法初判和模型意见。
- `take` 需要看到包裹离开原支撑并受手控制；`put` 需要看到包裹放到目标支撑并松手或稳定放置；片段开始时已经持有且看不到拿起起点时使用 `carrying`。证据不足保留 `uncertain`。
- 保留源视频帧号、媒体时间、原始证据与引用。失效观测、插帧和预测位置不能冒充真实动作证据；人物和层号冲突保留未知状态。
- 更换视频须重新检查首帧包裹框、货架区域和坐标系。复用观测需要相同视频哈希和配置。

## 六字段公开契约

以 `contracts/interaction_event.schema.json` 和 `station_vision/interaction/review.py` 为准：

```text
id, person_id, start_ms, end_ms, action, shelf_level
```

- `id` 在本次运行内唯一；人物未知或归属冲突时 `person_id=null`。
- 时间为源视频相对毫秒，满足 `0 <= start_ms <= end_ms <= 视频时长`。
- `action` 使用契约枚举，不把仅有接近的候选直接写成确认动作。
- 货架从下往上编号，最低储物板为第 1 层，顶层储物板计入，地面不计。拿取对应原支撑层，放置对应目标支撑层。
- 层号未知、冲突或不适用时为 `null`。不能只凭手的高度猜层号。Schema 的 1–20 是校验上限，不代表现场层数。
- 额外测量、证据依据和冲突放内部详情。只有当前用户需求明确改变公开接口时才修改六字段契约，并同步消费者与说明。

## 多帧复核与可视化

- Qwen 处理候选的动作前、中、后证据，复核算法初判。不要把当前程序描述为全程大模型解析，也不要把 `near_only` 包装成算法已确认拿取。
- 无 `-ReviewWithQwen` 时不调用 API；当任务需要真实复核且已有用户授权时使用现有配置。解析、聚合和导出调试优先复用已保存响应；复用观测仍可能产生新的模型请求。
- 密钥来自 `STATION_VLM_API_KEY` 或现有 DPAPI 存储，不写入源码、技能、文档、日志或 Git。
- 模型只能引用输入中允许的人物、帧和时间。复核失败、证据不足或遮挡时保留失败或未知状态，不补造成功结果。
- 联合视频应显示人物 ID、姿态、包裹位置、候选／动作时间和货架层。人物未知显示“人物未确定”，层号未知显示未知／不适用；标注应体现结果来源和确定性。

## 修改与验收

按改动选择相关检查，不为纯文档重复跑整段视频。候选和运动逻辑用现有测试与短片；解析、聚合或导出优先用已保存模型回答；新视觉算法用同视频比较漏检、跟丢、串人、错误候选和证据完整性。

实时性改动测量图像到候选的延迟、处理各阶段耗时和队列积压，区分显示帧率、算法观测频率及模型确认延迟。新增检测器或跟踪器通过可配置适配接入，保持已有主流程可运行。

每次运行使用新的 `RunName`。交付实际改动、解释器、已执行验证、结果位置和未测试事项；源码提交限定本任务文件，不把输入视频、权重、环境、凭证或其他人的未完成文件纳入提交。
