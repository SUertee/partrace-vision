# vision_runtime.json 参数说明

更新日期：2026-10-16。本文逐项解释同目录的 `vision_runtime.json`，对应当前 A 自动建档 → B 货架交互与人物关联主流程。

生成时配置SHA256：`575176b4cbaf15a4728057184f6de29bbbc86b4685fcfa8d851415203b541f9d`。共 **113个运行参数，17个参数组**。

## 如何使用本说明

- “当前值”读取自生成本文时的JSON；“代码默认值”是程序补全缺失字段使用的值。两者不同也不代表程序错误。修改JSON后本文不会自动更新。
- 实际生效的是JSON前面的各节，例如 `interaction.enter_ms`。`_help` 中的 `default`、`range`、`recommended` 是说明，修改它们不会修改运行值或代码校验范围。
- 数值不要加引号，JSON不支持 `//` 注释。`_help` 是以合法JSON字段保存的注释说明。
- 合法范围表示代码允许的输入范围，不表示范围内每个组合都准确、快速或适用于所有视频。推荐值是初始探索建议，不是跨场景最优值。
- 本文列出参数用途和当前实现，不代表已经完成所有自适应。绝对尺寸/模糊度门槛仍是固定值，匹配阈值尚未完成跨场景校准。
- 时间单位ms为源视频媒体时间，不是程序计算耗时。带 `_at_720` 的像素距离会按当前画面宽度/720缩放；并不要求输入必须为720宽。
- 检测置信度、外观余弦相似度、图像质量评分和多模态自评分是不同量，不能互相替代，也不能直接称为真实概率。

## 与服务器、视频和业务的关系

| 类型 | 主要参数 | 选择依据 |
|---|---|---|
| 服务器和处理预算 | CPU线程、imgsz、A采样频率、A/B外观提取频率、候选缓存上限、ORB特征数量 | CPU/GPU/显存/内存、并发视频路数及速度目标 |
| 视频条件敏感 | 人物最小尺寸、清晰度、遮挡、边缘截断、轨迹时长、伸收位移和配准几何条件 | 分辨率、人物远近、光照、压缩、拥挤、机位与动作速度 |
| 通用判据与证据策略 | 检测门槛、匹配相似度/分差、确认次数、支持数量和覆盖率 | 用多场景样本验证，不应靠降低门槛强行增加已识别数量 |
| 产品要求 | 每次合格轨迹3～5张、有效代表图最多5张 | 当前用户需求，不是某段视频自动产生的数值 |
| 远端模型服务 | 模型ID、API地址、超时、输出token上限 | 服务兼容性、网络、延迟与费用，不由本机GPU显存直接决定 |

固定的算法默认阈值并不等于绑定某个视频，但没有完成跨场景验证就不能保证通用效果。当前文件没有写入某段视频的人物ID、人物坐标或预先指定的识别答案。货架多边形位于单独标定JSON，本文不把它们混成模型参数。

## 启动参数与GPU

在项目目录使用唯一环境 `.venv-track`。下列命令由启动脚本选择该环境，不依赖终端是否激活。

```powershell
.\run_AB_station.ps1 -Device cuda
.\run_AB_station.ps1 -Device cpu
# 指定另一份配置，并启用五帧复核：
.\run_AB_station.ps1 -Device cuda -RuntimeConfig 'configs/vision_runtime.json' -ReviewWithQwen
```

`-Device`不在JSON内。cuda使人物姿态和OSNet使用NVIDIA GPU；解码、货架配准及可视化主要仍使用CPU。`cpu_threads`只设置PyTorch CPU线程，不等于整个程序的线程上限。B当前按源视频逐帧做人物/配准观测，`b_matching.feature_fps`只控制外观提取频率，不控制B姿态和配准的频率。GPU运行不等于实时。

`-ReviewWithQwen`才开启真实API请求。没有该开关，即使JSON配置了模型和地址也不会调用API。凭证来自环境变量或现有DPAPI存储，不放入JSON或本文。

## 加载优先级和结果复用

A使用RuntimeConfig指定的文件，默认同目录vision_runtime.json。A/B顺序入口向两阶段传入同一路径。B显式RuntimeConfig优先；未显式提供时，先保留场景配置中的runtime_parameters；新的普通运行再使用默认文件。旧观测复用不会静默套用最新JSON。

每次运行保存 `runtime_parameters.json`；B的 `config_snapshot.json` 也保存实际参数。改参数后下次运行生效，不是运行中热更新。修改配置会触发旧观测复用的一致性检查；当前要求视频、配置和档案哈希相同，不要将改参后的结果冒充旧配置复现。

## 参数之间的约束

- `a_video.feature_fps <= a_video.sampling_fps`。
- A/B `imgsz`均须为32的整数倍，`track_low_thresh < track_high_thresh`。若detection_conf高于track_low_thresh，低置信度框会提前被过滤，第二阶段续轨作用会减少。
- `a_keyframes.minimum <= a_keyframes.maximum <= archive_matching.maximum_templates`，数量范围为3～5。
- `archive_matching.minimum_support <= a_keyframes.maximum`。
- `b_matching.retain_threshold <= b_matching.threshold`。
- `hand_geometry.uncertainty_min_ratio <= hand_geometry.extension_ratio <= hand_geometry.uncertainty_max_ratio`。
- `reach.withdrawal_min_ms <= reach.withdrawal_window_ms`。
- 非法范围、错误类型或未知参数名会报错；上面的约束不是在_help中改范围就能解除。

## 01 A视频采样与轨迹时长：`a_video`

决定从A视频中多频繁观察人物，以及轨迹至少存在多久才进入建档。

实现位置：`station_vision/reid/enroll_video.py`。

### `a_video.sampling_fps`

- **当前值 / 代码默认值**：`15` / `15`。
- **类型、单位与合法范围**：整数；fps；1～60。
- **作用**：A人物检测/姿态目标采样频率，实际受源帧率限制。
- **调大或调小**：调大——更容易覆盖快速经过的人，推理耗时增加。 调小——计算更少，但可能漏掉短暂经过或转身。
- **参数性质**：服务器/处理预算；同时受输入帧率、人物大小或数量影响。
- **初始建议范围**：`[10, 20]`；需实测，不是保证。
- **使用注意**：这是目标观测频率，不是导出视频FPS或实时性能保证。源帧率低时不会补造帧。

### `a_video.feature_fps`

- **当前值 / 代码默认值**：`5` / `5`。
- **类型、单位与合法范围**：整数；fps/人；1～30。
- **作用**：A每条轨迹提取OSNet及选帧候选的最高频率。
- **调大或调小**：调大——候选更密，外观特征计算更多。 调小——更省算力，短轨迹可能不足三张有效图。
- **参数性质**：服务器/处理预算；同时受输入帧率、人物大小或数量影响。
- **初始建议范围**：`[3, 8]`；需实测，不是保证。
- **使用注意**：每条人物轨迹的最高特征提取频率，不能大于a_video.sampling_fps；多人会增加总计算量。

### `a_video.minimum_track_ms`

- **当前值 / 代码默认值**：`500` / `500`。
- **类型、单位与合法范围**：整数；ms；0～10000。
- **作用**：轨迹持续时间不足此值时不建档。
- **调大或调小**：调大——拒绝更多短轨迹，但可能漏掉快速经过者。 调小——允许短暂经过者，误检轨迹更容易进入选帧。
- **参数性质**：视频时间/机位/动作或几何策略；不是服务器速度设置。
- **初始建议范围**：`[300, 1000]`；需实测，不是保证。
- **使用注意**：依据源视频时间计算。过短或证据不足的轨迹会明确拒绝建档，不用重复图补足数量。

## 18 JSON中的说明字段

`_help`是说明索引，不参与算法计算。其每个参数条目含义如下：

| 字段 | 含义 | 修改后是否改变运行行为 |
|---|---|---|
| default | 编写说明时记录的默认值 | 否；代码默认值来自runtime_parameters.py |
| type | 说明中的整数/数值类型 | 否；实际类型校验仍由代码执行 |
| range | 说明中的合法范围 | 否；不能通过改它绕过校验 |
| unit | 单位 | 否 |
| meaning | 参数作用 | 否 |
| increase / decrease | 调大、调小的影响 | 否 |
| recommended | 初始探索建议范围 | 否；不是跨场景最优值 |
| warning | 模型兼容等使用提示 | 否 |

`_note`是整个文件的说明字符串，也不参与计算。代码会忽略以下划线开头的顶层元数据字段。真正要改的是实际参数，例如把 `interaction.enter_ms` 的300改为500，而不是修改 `_help.interaction.enter_ms.default`。

## 20 调参顺序

1. 先按服务器确定Device、线程、输入尺寸、观测/特征频率和缓存预算，测实际吞吐与延迟。
2. 再检查代表图质量，观察是否因小框、模糊或遮挡被大量拒绝；当前没有自动保证各种视频都适用的质量门槛。
3. 用多人物、多机位、多光照的独立标注片段验证匹配阈值，记录错关联和未知，避免只追求更多G编号。
4. 对照原视频检查交互起止、中间三帧和层号，不把腕点接近、估计手区或模型自评分当作接触/取件证明。
5. 每次改变一类参数，保留新RunName、实际参数快照及人工核查结果。代码运行成功不等于语义识别准确。
