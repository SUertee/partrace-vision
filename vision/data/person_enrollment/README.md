# 人物档案目录

自动档案现直接放在本目录，不再增加auto_archive一层。打开 `index.html` 可查看有效代表图。

```text
archive.json              全部档案特征与出现记录
profile_registry.json     编号保留表，不要手工清空
index.html                人物档案浏览页
G0004/                    单个人物档案
  profile.json            有效图片及来源说明
  *.png                   3～5张有效代表图
  history/                被替换的旧图片，保留、不参与默认匹配
```

A每条合格轨迹只导出精选3～5张截图，候选图在内存筛选，不逐帧落盘。最多五张有效档案图；样本不足时明确拒绝新建档案。历史手工档案只有1～2张的仍保留，页面会注明不足。参数在 `configs/vision_runtime.json`。

以下是保留的旧手工截图输入方式。自动G编号目录不会被该入口重新建档。不要与自动建档同时运行。

请把截图放在这里。每个人使用独立子文件夹，例如：

```text
person_001/    第一位人物的3—5张截图
person_002/    第二位人物的3—5张截图
person_003/    第三位人物；需要时自行新建
```

支持 JPG、JPEG、PNG、BMP、WEBP。文件名不限，推荐 01.jpg、02.jpg 等。

- 同一个文件夹只放同一个人；不同人不要混在一起。
- 推荐清晰的全身或大半身截图，适当包含正面、侧面、背面，不要只截脸或手。
- 尽量裁成单人图，保留衣服、裤子、背包等外观。如果整帧里有多人，请先裁出要建档的那个人，程序不会猜哪一个才是目标。
- 尽量使用不同时间的画面，不要把同一张图复制多次。
- 只有1—2张可用于试运行，但默认至少3张有效图才能建档；模糊或无法检出人物的图片会在报告中说明。
- 空文件夹不代表已建档。程序不会自动从其他视频填充这里。

程序会自动为有效文件夹建立档案编号，并保存编号与文件夹的对应关系。B中没有匹配到档案的人先显示U0001等未知编号，持续观察后，达到匹配条件再显示档案编号。

本目录是输入资料，不是算法结果。截图不会纳入Git提交。
