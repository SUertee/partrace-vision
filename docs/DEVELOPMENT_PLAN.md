# ParTrace Vision（驿站追迹）首轮开发计划

不盯屏，也能看清驿站每一天。

首轮目标：用固定区域的真实预录素材，让同一事件完成入库、Android 查询与开帧、Agent 引用、人工保存和重启回读。

[模块设计](modules/README.md) 记录全部业务模块的开发内容、表读写、API 提供／调用及交接边界；本页维护工作包依赖与验收，两者共同用于开工。

**状态快照：2026-10-17（Asia/Shanghai）。** 本页依据本地代码及已有验证记录更新，本轮仅核对文档，未重新运行业务测试或核验远端 Issue、合并与部署状态。本地工作区含尚未提交的实现；下列状态区分代码、局部实测与完整工作包验收，不据此将 D01–D10 整包标为完成。

Android 三入口、Backend／Agent 数据服务与独立 Vision worker 已有实现。模拟器已连接真实摄像头，A 原片完成过下载、上传、解析与状态回读；B 原片已排队，仍缺现场标定／区域映射。外部 Chat 模型已实测生成计划，正式运行仍有失败；真实区域事件的 Agent 引用、人工保存与重启回读尚未通过 D10。最新凭据见 [People 原片先入库后解析](../openspec/changes/d06-people-recording-pipeline/verification.md#先入库后解析--2026-10-17-最新验证)与 [Android Agent 验证](../openspec/changes/d07-android-agent/verification.md)。

主端为 Android，优先复用官方 KMP/Compose 示例。Web 桌面查阅后置；订单—货架映射、跨镜关联不进入首轮闭环。

**比赛展示策略（2026-10-14 确认）：** 先完成可安装、能跑通核心流程的 Android App。现场展示采用电脑安卓模拟器或安卓真机投屏，具体方式后续根据设备和场地条件确定；录屏为必交付，用于讲解与现场备用。模拟器可用于开发和演示彩排，Android 真机检查及 D06 摄像头 SDK 实测仍按各自验收要求执行。

## 顺序与并行

1. D01 先确定范围，再冻结共享协议。范围确定后，D02、D03、D06 和 D07 的服务入口可以准备。
2. 协议冻结后，四人用同一份样例并行推进 D04、D05、D07、D08、D09；同一人的任务按个人资源排顺序。
3. 真实产物交接为 **D04 → D05 → D07 / D08 / D09 → D10**。样例接通仅证明接口和交互可用，真实闭环仍须用实际视频事件验收。
4. D06 是独立支线，结果单独记录，不阻塞预录素材闭环。D10 先联调，再补齐首页与简报并验收。

当前共享契约为 [12 表／104 字段](database/README.md) 与 [0.3 API 草案](api/API_DESIGN.md) 的 35 个设计操作；Backend 默认实现 21 个，启用 Agent 后共 30 个。包裹单号与入出库两表、五个接口已纳入设计，业务实现仍为后续包裹阶段，不改变 D01–D10 的首轮验收范围。契约和代码已有交付，不代表固定素材、模型空间与全员协议冻结已完成。

存储使用 PostgreSQL + pgvector：业务与向量同库分表，时间用 TIMESTAMPTZ、JSON 用 JSONB。已实现限定范围的精确检索，ANN 索引按后续实测决定；服务端统一 Python，API 框架采用 FastAPI；Backend 与 Agent 分模块、共用 API 应用，Vision 独立工作进程领取原片任务并交接结果包。development 媒体使用受限本地文件存储；Chat 模型已有计划实测，Embedding 的 model／dimensions／key 仍未配置，外部语义检索及完整模型运行未验收。当前运行凭据只证明本地服务，不代表生产部署。
