# ParTrace Vision（驿站追迹）首轮开发计划

不盯屏，也能看清驿站每一天。

首轮目标：用固定区域的真实预录素材，让同一事件完成入库、Android 查询与开帧、Agent 引用、人工保存和重启回读。

[模块设计](modules/README.md) 记录全部业务模块的开发内容、表读写、API 提供／调用及交接边界；本页维护工作包依赖与验收，两者共同用于开工。

**2026-10-17状态更新：dev已有Backend/Agent和A/B离线算法；本地Android、真实SDK、People A链路及Agent接口已有验证，完整B、真实Agent执行、人工核查App闭环和D10未完成。下列状态区分dev已有源码与本地待合入实现，依据见[实际进展与待验收项](PROJECT_STATUS.md)。**

主端为 Android，优先复用官方 KMP/Compose 示例。Web 桌面查阅后置；订单—货架映射、跨镜关联不进入首轮闭环。

## 顺序与并行

1. D01 先确定范围，再冻结共享协议。范围确定后，D02、D03、D06 和 D07 的服务入口可以准备。
2. 协议冻结后，四人用同一份样例并行推进 D04、D05、D07、D08、D09；同一人的任务按个人资源排顺序。
3. 真实产物交接为 **D04 → D05 → D07 / D08 / D09 → D10**。样例接通仅证明接口和交互可用，真实闭环仍须用实际视频事件验收。
4. D06 是独立支线，结果单独记录，不阻塞预录素材闭环。D10 先联调，再补齐首页与简报并验收。

当前 D01 本地评审按 [11 表最小设计（80列）](database/README.md) 与 [0.3 API 草案](api/API_DESIGN.md) 收敛；已有部分实现，下列验收条件仍用于区分代码完成与业务验收，不代表协议已冻结。包裹单号与入出库两表、五个接口已纳入设计，业务实现作为后续包裹阶段，不改变 D01–D10 的预录视频首轮验收范围。

存储选型已确定为 PostgreSQL + pgvector：业务与向量同库分表，时间用 TIMESTAMPTZ、JSON 用 JSONB。先实现限定范围的精确检索，再按实测决定 ANN 索引；服务端统一 Python，API 框架采用 FastAPI；首版 Backend 与 Agent 分模块、共用 API 应用，Vision 独立工作进程交接结果包。模型、向量维度和媒体存储方案仍待确认；development服务已存在，生产部署另行验收。

## 完成凭据

每个工作包在 Issue 中维护主责、依赖、当前状态及交付链接，代码改动通过 PR 关联工作包。满足验收条件并附可复查凭据后，再更新为完成。
