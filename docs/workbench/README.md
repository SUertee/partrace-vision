# 项目工作台

[index.html](index.html) 包含总览、六屏原型、开发模块、数据库设计、API 设计、SDK/API 与 Demo 分工表、开发流程和飞书文档入口。

开发模块页集中展示“服务与技术方案”：Android 使用 Kotlin + Compose，Backend 使用 Python + FastAPI，Agent 使用 Python 并在首版接入同一 API 应用，Vision 使用独立 Python 工作进程，存储采用 PostgreSQL + pgvector。表内模块名称可打开对应开发说明或数据库页；模块详情显示技术与运行方式，SDK/API 与 Demo 对照表收进可展开的参考区。模型和媒体存储方案待确认，当前业务服务尚未实现。总览只保留一行技术说明，开发流程仍负责顺序与验收。

包裹扫码入出库在开发模块图中作为 P1 拓展支线，连接管理员 App 与后端；模块选择区单独列出，首轮模块数仍为 5。点开可查看二维码、扫码、确认流水、分工与验收，并跳转现有包裹表和 API 页面。开发流程在 D10 主闭环后列出“建档与查询 → 二维码生成与扫码 → 确认与流水 → Agent 只读历史”。它复用既有 Android、后端和 Agent，不新增页面或独立服务；扫码只查询，管理员确认后登记。业务实现仍待开发。

总览集中说明六步用户流程：看活动简报 → 提出问题 → 修改并确认 AI 计划 → 查看候选与证据 → 人工核查保存 → 从记录回查。四项核心展示为 AI 活动简报、一句话溯源、事件与证据回看、人工核查留档；流程和功能可打开对应原型。演示以同一事件的真实证据引用和保存后重启回查为验收点。

首版仍是固定区域的真实预录素材闭环。扫码入出库已有数据库/API 草案，后续阶段实现；持续直播分析另做能力验证。总览的阶段说明与功能目标不代表已完成真实业务验收，原型中的数据和回答为模拟。

从 GitHub 下载 HTML 后双击打开；GitHub 文件页显示源代码，不直接渲染网页。该文件已内嵌样式和脚本，无需启动服务。

侧栏品牌区域的按钮可收起或展开导航；桌面收起后保留图标入口和展开按钮，首次在平板宽度打开时默认收起。显式选择会保存在当前浏览器中，旋转屏幕后优先沿用；禁用浏览器存储仍可正常切换。手机收起后保留一行导航图标与切换按钮。

离线导航只处理新增链接或实际变更的地址，已改写的链接不再重复写入，避免 `file://` 下的属性监听循环。数据库图隐藏时暂停布局重算，再进入后恢复；原型和模块图仍按需加载。

同页点击模块、切换原型或重复选择当前导航时保留滚动位置；只有切换到另一页才回到页顶。从其他页面进入指定模块仍可定位开发说明，同页选择不自动滚动到详情。

数据、画面示意和 AI 回答是模拟样例。核查记录保存在各自浏览器中；工作台不提供真实后端或任务同步。开发任务以 [D01–D10](../DEVELOPMENT_PLAN.md) 和 GitHub Issues 为准，工作台中的阶段说明用于查看开发链路。

数据库设计可从侧栏、首页或开发模块中的“数据协议”进入，也可直接打开 [index.html#database](index.html#database)。工作台通过内嵌 `srcdoc` 展示 [最新关系图](../database/schema-canvas.html)，无需请求其他本地文件或启动服务。当前选型为 PostgreSQL + pgvector，11 表、77 字段，按视频素材、事件与检索、AI 会话与运行、账号与核查、包裹与入出库五个数据模块分组。默认展示全部，顶部筛选模块，点击表在右侧看字段；完整约束和相关 API 按需展开。API 标记当前草案或建议新增；页尾可查看新增表的功能条件。切换工作台页面后保留当前图内选择。

默认关系图使用全部宽度；点击表后才出现右侧字段区，关闭或清除选择后恢复全宽。平板选表后保留“左侧关系图、右侧字段”的布局，两个区域各自滚动；内嵌页只有窄至 480px 以下才改成上下排列。搜索、模块筛选与显示选项统一为一行，窄屏在工具栏内横向滑动；显示选项菜单在滚动容器外定位，避免被裁剪。内嵌图的高度随工具栏和页尾内容调整，不按固定工具栏高度估算。图按整页宽度布局，打开或关闭详情后让原表保持可见，收起导航或旋转屏幕时保留表的选择。

点表打开字段区时，关系图保持原有模块排列，整体等比例缩小到左侧可用宽度；关闭后恢复原来的手动倍率。缩放按钮仍可调整大小，只有实际窗口尺寸或可见表集合改变时才重新布局。右侧字段文字保持原字号。

关系图的源文件由 [数据库生成脚本](../../scripts/build-schema-canvas.py) 生成。源图更新后，在仓库根目录运行：

```sh
python3 scripts/sync-workbench-schema.py
python3 scripts/sync-workbench-schema.py --check
```

[同步脚本](../../scripts/sync-workbench-schema.py) 只更新 `WORKBENCH_OFFLINE_DOCUMENTS.database` 和对应来源哈希，给内嵌 HTML 根节点加 `embedded` class。它保留旧协议图、App 原型、模块关系图与源码导出功能，不重新生成整个工作台。重复运行结果相同；`--check` 仅检查是否同步。独立关系图源文件不受修改。

同步前会检查源图中的表定义与当前目录、SQL 一致，避免把旧图再次嵌入。可用 `python3 scripts/build-schema-canvas.py --check` 检查源图是否为最新生成版本。同步完成只代表离线 payload 与来源一致。页面交互和数据库内容均为评审材料，不能替代真实服务、SDK 或业务验收。

PostgreSQL 类型及目录来自临时实例的真实系统目录导出；关系图显示原生 `vector` / `JSONB` / `TIMESTAMPTZ`。线上工作台只发布静态设计，不部署数据库或模型服务。

`parcels / parcel_records` 已直接放进数据库关系图，包裹创建、单号查询和入出库五个接口直接放进 API 页，不保留独立“包裹与扫码”页面。二维码从单号生成，扫码先查询、管理员确认后才追加流水；设计说明见 [包裹草案](../database/PARCEL_DESIGN.md)。这些为 SQL/OpenAPI 草案，业务服务尚未实现。

## API 设计页

从侧栏进入 [API 设计](index.html#api)，或在开发模块详情点击“查看相关 API”。按 Android、视觉算法、后端、Agent 筛选交接接口；行内展开用途、关联表及来自当前 OpenAPI 的参数/模拟样例。27 个当前草案与 5 个待确认建议分别展示，接口未实现。

[独立 API HTML](../api/api-canvas.html) 与工作台内嵌版本均可离线打开，不发送真实 API 请求。API 页面首次进入时才挂载一个 `srcdoc` iframe，切换页面后保留筛选；`#api/backend` 等模块入口会定位对应分工。内嵌返回/数据库链接由工作台接管，避免请求部署中不存在的相对文件。

```sh
python3 scripts/build-api-canvas.py
python3 scripts/build-api-canvas.py --check
python3 scripts/sync-workbench-api.py
python3 scripts/sync-workbench-api.py --check
```

API 生成器检查 OpenAPI、模块映射、表映射和样例来源；同步脚本只更新 API payload 与来源哈希，保留原型、模块图和数据库图。数据库同步仍使用上面的独立脚本。
