## Context

本 change 属于 D07（Issue #7），依赖既有 `d07-android-agent`。当前 `StationApp` 保存各 Tab 的页面状态，Android 宿主根据当前页面和 Activity 生命周期调用 `TraceAgent.setActive`；控制器从本地快照恢复会话、确认计划与稳定运行 ID。AI 的事件片段通过 Voyager 打开详情，返回时也会重新激活 AI 页。因此页面激活本身不能区分用户点 Tab 和返回同一对话。

本次只调整 Android 客户端入口策略，使用 [M06 模块](../../../docs/modules/README.md#m06) 的既有会话、消息和运行能力。API、DB 与后端授权方式保持兼容，不新增服务端会话状态或空会话创建请求。

## Goals / Non-Goals

- 目标：明确点击首页、事件页或我的页的 AI 追溯 Tab 后，默认显示空白新对话；历史由用户主动选择。
- 目标：保留未完成真实分析的稳定 ID，继续支持恢复、显式停止和结果不明时的幂等回读。
- 目标：证据返回、前后台切换和 SDK 会话重建继续同一对话，服务设置入口不触发新对话。
- 非目标：修改 API／DB／服务端、删除历史、预先创建空会话、调整模型或摄像头能力、完成 D10 验收。

## Decisions

### 1. 入口意图与生命周期分开

新对话请求只由明确点击 AI 追溯 Tab 产生。宿主与控制器接收该意图，不把一般 `setActive(true)`、Compose 重组或 Screen 重新进入 composition 解释成新对话。事件证据详情返回、Activity 前台恢复及 SDK 会话重建继续既有恢复路径。服务设置入口只打开设置。

### 2. 初始化与入口重置串行处理

控制器先完成一次本地初始化，再处理新入口意图，然后读取所需录像元数据或决定恢复运行。不能由 UI 并行发送初始化、恢复和新建操作，让忙碌门禁丢弃其中一个请求。新入口决定必须在恢复旧消息或旧终态运行之前生效，避免旧对话在新入口后重新覆盖页面。

重置会话、持久指针与 UI 状态沿用当前持久化约束；本地保存失败应显示可诊断错误，不继续把旧会话当成新会话发送问题。异步请求取消后不能重新发布已丢弃的旧消息、计划或证据。

### 3. 新入口只重置本地当前对话

没有未完成真实运行时，清除本地 `conversationId`、`pending`、`lastRun`，以及页面消息、计划、运行、证据、相关分页状态和未发送草稿。后端地址、凭据及已选录像／区域保留，并继续按当前授权校验可用性。

服务端会话历史不删除；仅当用户实际提交新问题时，沿用既有稳定 ID 分配和持久化顺序创建会话。欢迎空态不应 POST 空会话。历史入口继续分页查询，用户明确选择后读取该会话消息。

### 4. 未完成真实运行保留恢复依据

真实运行仍为非终态，或已持久保存 `run_id` 但启动响应结果不明时，新入口不清除运行指针和确认载荷，继续按原 ID 恢复；不能通过新入口另分配运行 ID 或静默重跑。这是默认空白新对话的安全例外。已知 `completed`、`stopped`、`failed` 的运行不阻止下一次明确入口进入新对话。旧模拟来源继续遵循既有只读与新建真实分析门禁。

若恢复请求失败，保留稳定恢复依据并明确显示错误；不能将失败当成“没有运行”而清除本地指针。401／403 仍清除页面旧事实并停止自动请求，不能展示持久答案绕过当前授权。

## Risks / Trade-offs

- `rememberSaveable` 会保留未发送草稿，必须仅在明确的新入口被接受时清除，不能在证据返回或普通重组时清除。
- 清除当前会话与一般生命周期恢复的交错可能重新展示旧对话，因此入口处理与初始化／恢复必须有明确顺序，并用回归测试覆盖。
- 未完成运行是安全例外；保留原运行会暂时显示当前核查过程，但避免遗失停止依据或重复执行。允许并行新会话需要多运行本地存储设计，不纳入本次变更。
- 客户端构建和本地 HTTP 测试只能证明本次入口与恢复策略；摄像头和真实模型分析结果仍按各自验证记录判断。

## Verification Plan

新增针对冷初始化、既有终态会话的新入口、未完成运行与不明启动结果、历史手动打开及普通恢复的必要回归；运行既有 TraceAgent 测试、Debug 构建、lint 和 OpenSpec 检查。在可用设备分别操作 Tab 新入口、历史入口、证据往返和前后台恢复，保存实际环境与结果，未执行项保持未完成。
