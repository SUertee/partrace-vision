# Design

## Context

动机见 proposal.md。[开发计划](../../../docs/DEVELOPMENT_PLAN.md) 规定交付顺序；当前评审输入为 `dev@4d8e621` 的 10 个业务模块、11 表和 27 个 API 草案，来源 PR #12 已进入 dev。本 change 的验收对象是契约文档与样例，仍等待四方确认，不是业务程序。

## Goals / Non-Goals

让四方能用同一组场景核对契约，形成有版本、有样例、有确认记录的基线。运行性能、模型效果、SDK 真机和端到端持久化由对应开发工作包实测。

## Decisions

- 采用单一 shared-contracts 能力记录交接行为；业务模块以 docs/modules 为入口，DB 定义以 schema.sql 为准，HTTP 字段以 openapi.json 为准。用 [场景关联表](scenario-map.md) 连接具体契约与样例，不建立平行字段定义。
- 将首轮行为分为完整录像事件查询、描述向量检索和 AI 运行状态。事件查询不包含全局采集台账／待处理索引；向量检索报告自身索引缺口。导入失败与模型／存储故障返回错误，不冒充无采集或无匹配。
- 使用视频偏移为定位基准；只有验证过起始时间才允许 UTC 查询。SQL 绝对时间用 TIMESTAMPTZ，API 用同名 UTC 字符串；不新增 epoch_ms 字段。
- 证据只有 available／missing；删除或失效仍保留稳定 ID 和历史，媒体读取返回明确缺失错误。人工核查一次一个事件，独立追加保存，不改变原事件。
- Agent 的事实工具只读，自己的会话／消息／运行可以持久化；会话不绑定录像，每次运行仍单视频，读取／停止／重试和完成答复按本次范围验权。completed 状态与唯一完整答复原子提交；停止／失败无伪完成消息，重启不自动续跑。
- PostgreSQL + pgvector 与 Python + FastAPI 已选定；Backend／Agent 首版分模块共用 API 应用，Vision 独立进程。M10 包裹两表／五接口仅保留 P1 设计，后续 change 评审，不成为首轮前置。
- 各模块确认结果和剩余依赖写入 Issue #1。tasks 完成意味着本 change 的契约交付完成；D01 仍须按开发计划核对固定素材、范围与三个查询，不因归档自动关闭。

## Risks / Trade-offs

- 当前草案仍可能调整：基于所记录 dev 版本评审，同步受影响模块、SQL／OpenAPI、样例和派生页面。
- 仅模拟样例通过：明确来源，保留 D04-D10 的真实验收要求。
- 旧样例消费方落后：记录版本、受影响模块与迁移方式，禁止静默更改 ID 或时间解释。

## Migration Plan

本次更新活跃 D01 提案，并保留 2026-10-12 工具接入归档和官方生成入口。原 v0.2／SQLite 资料留在历史目录，不能用来验收 v0.3。完成固定素材、查询和四方确认后才归档；发生分歧时保持活跃。格式与离线同步检查不代表真实数据库、媒体、模型或 D10 已通过。
