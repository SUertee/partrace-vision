## Context

用户指定当前设备首页的蓝白渐变、圆角白卡和底部胶囊导航。当前官方事件页面包含调试筛选、下载与删除，既有 ViewModel 会在过滤结果到达前展示未过滤流；新事件页采用独立只读适配和展示层，继续复用图片请求与回放屏幕。

## Decisions

- 页面源码归入 `station/ui/events`，SDK 数据与可测试筛选逻辑归入 `station/events`。界面展示模型不保存 SDK 对象，只有日期、筛选 ID 和滚动状态进入 saveable；事件对象由 Voyager 根 ScreenModel 在内存保留并传给现有回放，登出销毁根状态；父设备列表短暂刷新或名称变化不清除同一摄像头范围的结果，刷新／已有结果错误提示不插入列表项，以免回放返回时移动索引。
- 主壳与页面恢复白名单添加 events，背景及状态栏沿用首页；共享底栏增加独立图标及可辨识选中态。AI 继续为独立全屏聊天，避免底栏与输入框／键盘叠加。
- 以当前账号真实摄像头列表建立父／子设备范围。SDK 查询使用所选本地日的起止时间，按设备及检测类型约束；适配层再次限定范围、去重和倒序，未知检测类型保留为其他检测。
- 使用 SDK 可取消回调及 30 秒超时。离开页面或切换范围取消旧请求，迟到结果不得覆盖当前范围；失败可保留同范围旧卡片并明确提示，换范围不能把旧结果当作新结果。
- SDK 成功回调可合并本地／云缓存，且不能证明所有来源都已刷新成功。因此页面说明结果可能含缓存；单次查询 count=200，达到上限保留可能不完整提示，本次不接未经验证的时间游标分页。
- 缩略图使用原 `rememberEventImageRequest`，缺图／失败显示占位，不使用真实画面以外的图冒充成功。录像路径和有效时长齐备才进入 `EventPlayScreen`；其他记录显示元信息与录像不可用说明。打开回放前再次确认设备存在。
- 设计预览注入明确样例，不初始化 SDK、不触发 People 自动处理或模型。用户参考图含真实画面，只在当前请求中作视觉参考，不复制到仓库作为公开设计截图。

## Verification

针对日期边界、设备／类型隔离、去重排序、上限、失败与取消运行实质单元测试；执行 Debug 构建及 lint、既有相关回归。通过无 SDK 副作用的 Compose 预览核对列表、空态和错误；有条件时分别验证实际事件查询和回放导航。APK 安装、设备操作、真实 SDK 结果及未验证项只按实际记录，不以构建代替真机。
